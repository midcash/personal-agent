# 已确认的目标行为与验收场景

产品正朝 Personal Agent 方向演进，当前聚焦已确认的个人日程目标（S01–S05：S01–S04 于 2026-11-05 由用户确认，S05 于 2026-11-06 确认；S01 的默认时区于 2026-11-06 由用户改为固定 UTC+8）。原保留的差旅子能力（B01–B12）已按 [ADR 003](adr/003-retire-travel-and-unify-node.md) 正式退役。目标不等于已经完成真实模型验收。

## 日程验收场景

### S01 会话创建与展示

通过会话创建标题、日期及起止时间明确的单次日程，前端日历对应位置出现。默认采用用户于 2026-11-06 改定的固定 UTC+8 时区（+08:00），允许用户明确指定其他时区；页面统一按 UTC+8 显示并使用中文。缺少标题、日期或起止时间先追问，不擅自补全时长。

### S02 查询与恢复

通过会话查询能读取同一条日程。刷新页面、重启服务后，会话与日程仍保留，日历显示一致。

### S03 重试不重复创建

同一次请求重试、工具恢复重放或重复确认，不重复创建同一条日程。

### S04 重叠先确认

新增日程与已有日程重叠时，寻求用户确认；未确认前不创建，也不自动调整已有日程。

### S05 会话修改、删除与改期

用户于 2026-11-06 确认：通过会话删除指定日程、修改指定日程内容，并组合工具调整日期（例如明天推迟至后天）。先查询定位，匹配不唯一时追问；未指定的内容保留。改期优先直接修改，避免先删后建失败造成数据丢失；修改产生重叠时沿用确认要求。真实模型对话验收与离线工具验证分别报告。

## 验收原则

- S01–S05 定义当前个人日程核心闭环的目标业务行为，不代表当前产品已经完成真实模型全量验收。
- 实现任务应明确本次覆盖哪些场景、可观察的成功结果及未覆盖范围。
- 技术架构和实现顺序由单独批准的实施任务确定；不得因为当前代码或历史方案存在某种机制，就改变上述业务语义。
